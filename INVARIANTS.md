# Testable Safety Invariants

Every claim in `README.md` that says "cannot" or "never" must have a
corresponding test in this document. If a test is missing, the invariant is
marketing, not engineering.

---

## 1. Kernel Plane (K)

| # | Invariant | Test |
|---|---|---|
| **K1** | No dynamic JVM classloading | `K1ClassloadingTest` — zero `defineClass` / `URLClassLoader` in production code |
| **K2** | No shell interpolation | `ProcessInjectionIT` — `;`, `$()`, `` ` ``, `\|`, `&&` reach binary as literals |
| **K3** | `IMMUTABLE_KERNEL_INVARIANTS` are compiled constants | `K3KernelInvariantTest` — compiled constant reflection check; no runtime write path |
| **K4** | Tool execution scoped to canonical workspace root | `RealPathJailTest` — `RealPathJail` rejects `../`, symlink escapes, and outside absolute paths |
| **K5** | No orphan processes after timeout or cancellation | `OrphanProcessIT` — `ProcessTreeTerminator` kills all `ProcessHandle.descendants()` |
| **K6** | Cancellation is prompt | `CancellationTokenTest` — canceled future observed within 100ms; process tree terminated within 500ms |
| **K7** | OS injection guarded by dead-man + rate limit + password block | `K7InputInjectionGuardTest` — dead-man switch, rate limit, and password field block |
| **K8** | No carrier pinning on the agent executor | Grep CI: zero `synchronized` / `Object.wait()` in `kernel.agent/**` and `kernel.web/**`; `PinningIT`: 500 concurrent virtual threads awaiting `Condition` complete within 5s on JDK 21 |

## 5. Sentinel Categories

Every commit generated by `writeWorkspaceFile` passes all six categories
before `ProposalCreated` is emitted. Any failure rolls the branch back to
its parent and emits `StreamError{code: "SANDBOX_REJECTED:<CATEGORY>"}`.

| Category | Pass condition | Failure code |
|---|---|---|
| **Structural** | Schemas valid, no path traversal, no absolute paths outside sandbox | `SANDBOX_REJECTED:STRUCTURAL` |
| **Security** | Zero credential regex hits (`AKIA[0-9A-Z]{16}`, `ghp_`, `sk-`, PEM), zero injection markers (`ignore previous instructions`, `</system>`, role-confusion) | `SANDBOX_REJECTED:SECURITY` |
| **Capability** | Every tool capability class covered by operator grant | `SANDBOX_REJECTED:CAPABILITY` |
| **Dry-run** | Every new tool executes its declared `probe` argv successfully (10s timeout, expected exit code, output parses to schema) | `SANDBOX_REJECTED:PROBE` |
| **Regression** | Replay last 20 messages: no guardrail trips, token count ≤110% of parent for identical inputs | `SANDBOX_REJECTED:REGRESSION` |
| **Budget** | System prompt ≤25% of grant; ≤80% of parent + 4K; `SKILL.md` files within tiered line limits (150 lines operational / 200 lines domain) | `SANDBOX_REJECTED:BUDGET` |

Each category has a parameterized test class with at least one passing
and one failing fixture. A category without both is treated as
unimplemented, not "implicitly passing."

## 6. Capability Escalation

Any commit that adds or modifies a tool declaring one of the following
capability classes requires a signed, non-expired `PermissionGrant` from
the operator, regardless of sentinel outcome:

- `WRITE` — writes to filesystem outside sandbox
- `NET_EGRESS` — network egress beyond `127.0.0.1`
- `PROC_SPAWN` — spawns subprocesses
- `SCREEN_INJECT` — synthesizes OS input events

The sentinel is an automated **gate**, not a replacement for human approval.

## 8. Non-Goals

The following are explicitly out of scope for the invariant suite and
must not be cited as guarantees:

- Formal verification of the sentinel (TLA+ is future work)
- Side-channel resistance (timing attacks on token counts, etc.)
- Physical security of the SBC host
- LLM hallucination prevention (mitigated by guardrails, not eliminated)
